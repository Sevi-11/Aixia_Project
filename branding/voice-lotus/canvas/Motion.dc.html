Binding the speaking state to real audio
// One rAF loop writes one custom property. Nothing re-renders.
analyser.getByteTimeDomainData(buf);
let s = 0;
for (const v of buf) { const x = (v - 128) / 128; s += x * x; }
const target = Math.min(1, Math.sqrt(s / buf.length) * 3.2);

// Fast attack, slow release — otherwise the bloom flickers on consonants.
amp += (target - amp) * (target > amp ? 0.45 : 0.12);
mark.style.setProperty('--amp', amp.toFixed(3));

/* CSS, no JS per petal: */
.speak .pt   { transform: rotate(calc(var(--d) * var(--m) * var(--amp) * 14deg))
                          scale(calc(1 + var(--amp) * 0.16)); }
.speak .seed { transform: scale(calc(0.9 + var(--amp) * 0.34)); }
Rules that keep it honest
—Reduced motion. Every loop collapses to a 420ms cross-fade between two static poses, closed and open. The state still reads; nothing oscillates.
—One state at a time. The mark has a single class. Overlapping animations are what make voice orbs read as broken.
—Screen readers. The SVG stays aria-hidden. State changes are announced from the text chip with aria-live="polite".
—Clamp before CSS. Amplitude is capped at 1 in JS, so a hot mic can never push the bloom past its frame.
—Cost. Five composited transforms, no layout, no paint. Safe to leave running on a mid-range phone.
